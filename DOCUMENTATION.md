## 1. Общее описание

**Cert Filter Ultra PRO** — десктопное приложение на Python (PyQt6) для управления
цифровыми сертификатами в хранилище Windows CryptoAPI / КриптоПро CSP.

### Основные возможности

| Функция | Описание |
|---------|----------|
| **Просмотр сертификатов** | Отображение всех сертификатов из хранилищ `MY` и `AddressBook` |
| **Фильтрация** | Скрытие всех сертификатов, кроме выбранного (по CN) |
| **Скрытие/Показ** | Установка/снятие флага `CERT_ARCHIVED_PROP_ID` |
| **Массовые операции** | «Показать все» / «Скрыть все» |
| **Просмотр деталей** | ИНН, СНИЛС, ОГРН, серийный номер, издатель, сроки |
| **Экспорт PFX** | Экспорт сертификата с закрытым ключом в `.pfx` файл |
| **Импорт PFX** | Импорт сертификата с ключом из `.pfx` файла |
| **Удаление** | Удаление сертификата и контейнера закрытого ключа |
| **Friendly Name** | Установка/редактирование дружественного имени сертификата |
| **Управление JSON** | Добавление, редактирование, удаление записей в конфиг-файлах |

### Назначение

Приложение предназначено для ситуаций, когда в хранилище установлено большое
количество сертификатов (например, 241), и нужно оставить видимым для браузерного
плагина КриптоПро только один конкретный сертификат. Это достигается установкой
свойства `CERT_ARCHIVED_PROP_ID` на все остальные сертификаты — после чего плагин
КриптоПро ЭЦП Browser plug-in их не отображает.

## 3. Архитектура приложения

Приложение состоит из двух логических слоёв:

```
┌─────────────────────────────────────────────────────┐
│                    UI (PyQt6)                       │
│  CertFilterApp (QMainWindow)                        │
│  ├── Левая панель: JSON, ключи, поиск, лог          │
│  └── Правая панель: список сертификатов              │
│                                                     │
│  CertWorker (QThread) — фоновая фильтрация          │
├─────────────────────────────────────────────────────┤
│               Backend (CryptoAPI / ctypes)           │
│  Функции:                                           │
│  ├── get_all_certs()       — список сертификатов     │
│  ├── get_cert_details()    — детали сертификата      │
│  ├── apply_filter()        — фильтрация по CN       │
│  ├── toggle_cert_archive() — скрыть/показать один    │
│  ├── restore_all()         — показать все            │
│  ├── hide_all()            — скрыть все              │
│  ├── export_pfx()          — экспорт в PFX          │
│  ├── import_pfx()          — импорт из PFX          │
│  ├── delete_cert_and_key() — удаление + контейнер   │
│  └── set_cert_friendly_name() — дружественное имя   │
├─────────────────────────────────────────────────────┤
│           CryptoAPI (crypt32 / advapi32)             │
│  Windows: crypt32.dll + advapi32.dll                 │
│  Linux:   libcapi20.so + libcapi10.so (КриптоПро)   │
└─────────────────────────────────────────────────────┘
```

### Потоки выполнения

- **Главный поток (Main Thread):** UI, обработка событий, отображение данных
- **Рабочий поток (CertWorker):** Фильтрация сертификатов (может занимать время при большом количестве)

## 4. Кроссплатформенная загрузка CryptoAPI

**Строки 26–33** — единственный платформозависимый блок:

```python
if sys.platform == "win32":
    crypt32 = ctypes.WinDLL("crypt32.dll")        # Windows CryptoAPI 2.0
    advapi32 = ctypes.WinDLL("advapi32.dll")       # Windows CryptoAPI 1.0
else:
    crypt32 = ctypes.CDLL("/opt/cprocsp/lib/amd64/libcapi20.so")   # КриптоПро CryptoAPI 2.0
    advapi32 = ctypes.CDLL("/opt/cprocsp/lib/amd64/libcapi10.so")  # КриптоПро CryptoAPI 1.0
```

| Переменная | Windows | Linux | Предоставляемые функции |
|------------|---------|-------|------------------------|
| `crypt32` | `crypt32.dll` | `libcapi20.so` | CertOpenStore, CertEnumCertificatesInStore, CertGetNameStringW, CertSetCertificateContextProperty, PFXExportCertStoreEx, PFXImportCertStore и др. |
| `advapi32` | `advapi32.dll` | `libcapi10.so` | CryptAcquireContextW, CryptReleaseContext |

> **Ключевой факт:** КриптоПро CSP на Linux полностью эмулирует Windows CryptoAPI,
> включая типы данных (FILETIME, DATA_BLOB), имена функций (с суффиксами W) и
> семантику (CERT_ARCHIVED_PROP_ID). Благодаря этому весь остальной код
> работает одинаково на обеих платформах.

### Объявления функций (строки 35–66)

После загрузки библиотек объявляются сигнатуры всех используемых CryptoAPI-функций
через `argtypes` и `restype`:

| Функция CryptoAPI | Назначение |
|-------------------|------------|
| `CertOpenStore` | Открыть хранилище сертификатов (системное или в памяти) |
| `CertCloseStore` | Закрыть хранилище |
| `CertEnumCertificatesInStore` | Перечислить сертификаты в хранилище |
| `CertGetNameStringW` | Получить имя из сертификата (CN, Subject, Issuer) |
| `CertGetCertificateContextProperty` | Прочитать свойство сертификата |
| `CertSetCertificateContextProperty` | Установить свойство сертификата |
| `CertDuplicateCertificateContext` | Дублировать контекст (увеличить счётчик ссылок) |
| `CertFreeCertificateContext` | Освободить контекст |
| `CertNameToStrW` | Преобразовать бинарное имя (Subject/Issuer) в строку X.500 |
| `CertDeleteCertificateFromStore` | Удалить сертификат из хранилища |
| `CertAddCertificateContextToStore` | Добавить сертификат в хранилище |
| `PFXExportCertStoreEx` | Экспорт хранилища в PFX/PKCS#12 |
| `PFXImportCertStore` | Импорт PFX/PKCS#12 в хранилище |
| `CryptAcquireContextW` | Получить/удалить контекст криптопровайдера |
| `CryptReleaseContext` | Освободить контекст криптопровайдера |

## 5. Структуры данных CryptoAPI (ctypes)

### DATA_BLOB (строка 84)

```python
class DATA_BLOB(ctypes.Structure):
    _fields_ = [("cbData", ctypes.c_ulong), ("pbData", ctypes.c_void_p)]
```

Универсальная структура для передачи бинарных данных (сертификаты, ключи, PFX и т.д.).

| Поле | Тип | Описание |
|------|-----|----------|
| `cbData` | `DWORD` | Размер данных в байтах |
| `pbData` | `BYTE*` | Указатель на данные |

### CRYPT_KEY_PROV_INFO (строка 87)

Информация о контейнере закрытого ключа, связанном с сертификатом.

| Поле | Описание |
|------|----------|
| `pwszContainerName` | Имя контейнера (например, `\\.\HDIMAGE\pfx-xxx`) |
| `pwszProvName` | Имя криптопровайдера (например, `"Crypto-Pro GOST..."`) |
| `dwProvType` | Тип провайдера (75 = GOST 2001, 80 = GOST 2012-256, 81 = GOST 2012-512) |
| `dwFlags` | Флаги |
| `cProvParam` | Количество параметров |
| `rgProvParam` | Указатель на массив параметров |
| `dwKeySpec` | Тип ключа (`AT_KEYEXCHANGE=1` или `AT_SIGNATURE=2`) |

### FILETIME (строка 98)

Время в формате Windows — 64-битное целое, представляющее число 100-наносекундных
интервалов с 1 января 1601 года.

```python
class FILETIME(ctypes.Structure):
    _fields_ = [("dwLowDateTime", ctypes.c_uint32), ("dwHighDateTime", ctypes.c_uint32)]
```

### CERT_INFO (строка 104)

Основная информация из X.509 сертификата (частичное определение — только нужные поля).

| Поле | Описание |
|------|----------|
| `dwVersion` | Версия сертификата (обычно 2 = V3) |
| `SerialNumber` | Серийный номер (DATA_BLOB, big-endian при отображении) |
| `SignatureAlgorithm` | Алгоритм подписи |
| `Issuer` | Издатель в бинарном формате (DER) |
| `NotBefore` | Дата начала действия (FILETIME) |
| `NotAfter` | Дата окончания действия (FILETIME) |
| `Subject` | Субъект в бинарном формате (DER) |

### CERT_CONTEXT (строка 115)

Контекст сертификата — основная структура, возвращаемая CertEnum/CertOpen.

| Поле | Описание |
|------|----------|
| `dwCertEncodingType` | Тип кодировки (обычно `X509_ASN_ENCODING = 1`) |
| `pbCertEncoded` | Указатель на DER-кодированный сертификат |
| `cbCertEncoded` | Размер DER-данных |
| `pCertInfo` | Указатель на `CERT_INFO` (разобранные данные) |
| `hCertStore` | Дескриптор хранилища, которому принадлежит контекст |

### Константы хранилищ

| Константа | Значение | Описание |
|-----------|----------|----------|
| `CERT_STORE_PROV_SYSTEM` | `10` | Провайдер системного хранилища |
| `CERT_STORE_PROV_MEMORY` | `2` | Провайдер хранилища в памяти |
| `CERT_SYSTEM_STORE_CURRENT_USER` | `0x00010000` | Хранилище текущего пользователя |
| `CERT_STORE_OPEN_EXISTING_FLAG` | `0x00004000` | Открыть только существующее хранилище |
| `CERT_STORE_MAXIMUM_ALLOWED_FLAG` | `0x00001000` | Открыть с максимальными правами |

| `CERT_STORE_ADD_REPLACE_EXISTING` | `3` | При добавлении заменять существующие |

| Константа | Значение | Описание |
|-----------|----------|----------|

| `CERT_FRIENDLY_NAME_PROP_ID` | `7` | Дружественное имя сертификата |
| `CERT_KEY_PROV_INFO_PROP_ID` | `2` | Информация о контейнере закрытого ключа |

| Константа | Значение | Описание |

| `CRYPT_DELETEKEYSET` | `0x00000010` | Удалить контейнер ключа |

### Формат имени

| Константа | Значение | Описание |
|-----------|----------|----------|
| `CERT_X500_NAME_STR` | `3` | Имя в формате X.500 (CN=..., O=..., и т.д.) |

## 7. Backend-функции (работа с сертификатами)

### `filetime_to_datetime(ft)` — строка 124

Конвертирует структуру `FILETIME` (Windows) в объект Python `datetime`.

**Алгоритм:**
1. Объединяет `dwHighDateTime` и `dwLowDateTime` в 64-битное число (`win_ticks`)
2. Делит на 10 для получения микросекунд
3. Добавляет к начальной дате Windows-эпохи (1 января 1601)

```python
filetime_to_datetime(ft) → datetime
```

---

### `iter_certs(store)` — строка 134

Генератор, перечисляющий все сертификаты в хранилище.

**Параметры:**
- `store` — дескриптор хранилища (из `CertOpenStore`)

**Возвращает:** итератор указателей на контексты сертификатов (`CERT_CONTEXT*`)

**Важно:** После вызова `CertEnumCertificatesInStore` предыдущий контекст
автоматически освобождается. Поэтому, если нужно сохранить контекст для
дальнейшего использования, его нужно дублировать через `CertDuplicateCertificateContext`.

---

### `get_name(cert) → str` — строка 142

Получает отображаемое имя сертификата (CN — Common Name).

**Параметры:**
- `cert` — указатель на контекст сертификата

**Возвращает:** строку с CN сертификата. Например:
```
"МУНИЦИПАЛЬНОЕ БЮДЖЕТНОЕ ДОШКОЛЬНОЕ ОБРАЗОВАТЕЛЬНОЕ УЧРЕЖДЕНИЕ \"ДЕТСКИЙ САД №5\""
```

**Внутренний вызов:** `CertGetNameStringW(cert, 4, ...)` — тип `4` = `CERT_NAME_ATTR_TYPE`,
возвращает атрибут `CN` из `Subject`.

---

### `is_archived(cert) → bool` — строка 150

Проверяет, установлено ли свойство `CERT_ARCHIVED_PROP_ID` на сертификате.

**Как это работает:**
- Вызывает `CertGetCertificateContextProperty` с `prop_id=19`
- Если свойство существует — сертификат архивирован (скрыт)
- Архивированные сертификаты не отображаются в плагине КриптоПро

---

### `set_archived(cert, archive: bool) → bool` — строка 154

Устанавливает или снимает свойство `CERT_ARCHIVED_PROP_ID`.

**Параметры:**
- `cert` — указатель на контекст сертификата
- `archive` — `True` для скрытия, `False` для отображения

**Алгоритм:**
1. Проверяет текущее состояние через `is_archived()`
2. Если состояние уже совпадает — ничего не делает
3. Для архивации: устанавливает свойство с пустым `DATA_BLOB`
4. Для деархивации: удаляет свойство, передавая `None` как значение

```python
# Скрыть сертификат:
set_archived(cert, True)   # → CertSetCertificateContextProperty(cert, 19, 0, &blob)

# Показать сертификат:
set_archived(cert, False)  # → CertSetCertificateContextProperty(cert, 19, 0, NULL)
```

---

### `get_cert_property(cert, prop_id) → str` — строка 163

Получает строковое свойство сертификата по идентификатору.

**Параметры:**
- `cert` — указатель на контекст
- `prop_id` — идентификатор свойства (например, `CERT_FRIENDLY_NAME_PROP_ID = 7`)

**Возвращает:** строку UTF-16LE → Python str

**Алгоритм двухфазного вызова:**
1. Вызов с `NULL`-буфером для получения размера
2. Выделение буфера нужного размера
3. Повторный вызов для заполнения буфера
4. Декодирование из UTF-16LE

---

### `set_cert_friendly_name(cert_name, new_friendly_name) → bool` — строка 175

Устанавливает дружественное имя (`Friendly Name`) сертификата.

**Параметры:**
- `cert_name` — CN сертификата (для поиска)
- `new_friendly_name` — новое дружественное имя

**Алгоритм:**
1. Перебирает хранилища `MY` и `AddressBook`
2. Находит сертификат по CN
3. Кодирует новое имя в UTF-16LE с нуль-терминатором
4. Устанавливает свойство `CERT_FRIENDLY_NAME_PROP_ID`

---

### `get_cert_details(name: str) → dict | None` — строка 195

Получает полную информацию о сертификате по CN.

**Параметры:**
- `name` — CN сертификата

**Возвращает словарь:**

| Ключ | Тип | Описание |
|------|-----|----------|
| `name` | `str` | Имя сертификата (CN) |
| `cn` | `str` | Common Name (тип 3) |
| `friendly` | `str` | Дружественное имя |
| `subject` | `str` | Простое имя субъекта (тип 1) |
| `issuer` | `str` | Имя издателя |
| `serial` | `str` | Серийный номер (HEX, big-endian) |
| `snils` | `str` | СНИЛС (из DN субъекта) |
| `inn` | `str` | ИНН физического лица |
| `inn_le` | `str` | ИНН юридического лица |
| `ogrn` | `str` | ОГРН |
| `not_before` | `datetime` | Дата начала действия |
| `not_after` | `datetime` | Дата окончания действия |
| `full_subject` | `str` | Полный DN субъекта в формате X.500 |

**Извлечение OID-полей из DN:**

Для извлечения российских OID-полей (СНИЛС, ИНН, ОГРН) используется функция
`find_oid()`, которая ищет по нескольким паттернам регулярных выражений:

```python
# СНИЛС — OID 1.2.643.100.3
snils_val = find_oid(full_subject_str, [
    r"СНИЛС\s*=\s*([\d-]+)",          # Кириллица
    r"SNILS\s*=\s*([\d-]+)",           # Латиница
    r"OID\.1\.2\.643\.100\.3\s*=\s*([\d-]+)"  # Числовой OID
])

# ИНН (физлицо) — OID 1.2.643.3.131.1.1
inn_val = find_oid(full_subject_str, [
    r"(?<!ЮЛ)ИНН\s*=\s*(\d+)",        # ИНН (но не ИНН ЮЛ)
    r"INN\s*=\s*(\d+)",
    r"OID\.1\.2\.643\.3\.131\.1\.1\s*=\s*(\d+)"
])

# ИНН юридического лица — OID 1.2.643.6.3.1.4.1
# ОГРН — OID 1.2.643.100.1
```

### `delete_cert_and_key(name: str) → bool` — строка 260

Удаляет сертификат из хранилища **вместе с контейнером закрытого ключа**.

**⚠️ НЕОБРАТИМАЯ ОПЕРАЦИЯ!**

**Алгоритм:**
1. Находит сертификат по CN в хранилищах `MY` / `AddressBook`
2. Читает `CERT_KEY_PROV_INFO_PROP_ID` — информацию о контейнере ключа
3. Вызывает `CryptAcquireContextW` с флагом `CRYPT_DELETEKEYSET` — удаляет контейнер
4. Дублирует контекст сертификата (`CertDuplicateCertificateContext`)
5. Удаляет сертификат из хранилища (`CertDeleteCertificateFromStore`)

> **Примечание:** Дублирование контекста перед удалением необходимо, так как
> `CertDeleteCertificateFromStore` освобождает переданный контекст, который
> может быть нужен для итерации.

---

### `export_pfx(name: str, path: str, password: str) → bool` — строка 287

Экспортирует сертификат с закрытым ключом в файл формата PFX/PKCS#12.

**Параметры:**
- `name` — CN сертификата
- `path` — путь для сохранения файла
- `password` — пароль для защиты PFX

**Алгоритм:**
1. Открывает системное хранилище `MY` и пустое хранилище в памяти
2. Находит нужный сертификат и копирует его в хранилище в памяти
3. Первый вызов `PFXExportCertStoreEx` с пустым `DATA_BLOB` — получает размер
4. Выделяет буфер нужного размера
5. Второй вызов — заполняет буфер данными PFX
6. Записывает буфер в файл

**Флаги экспорта:**
- `EXPORT_PRIVATE_KEYS` — экспортировать закрытый ключ
- `REPORT_NOT_ABLE_TO_EXPORT_PRIVATE_KEY` — вернуть ошибку, если ключ неэкспортируемый

---

### `import_pfx(path: str, password: str) → bool` — строка 321

Импортирует сертификат с закрытым ключом из файла PFX/PKCS#12.

**Параметры:**
- `path` — путь к PFX-файлу
- `password` — пароль от файла

**Алгоритм:**
1. Читает файл целиком в `DATA_BLOB`
2. Вызывает `PFXImportCertStore` — создаёт временное хранилище с импортированными данными
3. Открывает системное хранилище `MY`
4. Перечисляет сертификаты из PFX и добавляет каждый в системное хранилище

---

### `toggle_cert_archive(name: str)` — строка 345

Переключает состояние архивации сертификата (скрыт ↔ видим).

Находит сертификат по CN и инвертирует свойство `CERT_ARCHIVED_PROP_ID`.

---

### `apply_filter(target_cn: str) → (int, int)` — строка 363

**Основная функция фильтрации.** Оставляет видимыми только сертификаты,
содержащие целевой CN.

**Параметры:**
- `target_cn` — подстрока CN для поиска (регистронезависимый)

**Возвращает:** кортеж `(kept, hidden)` — количество оставленных и скрытых

**Алгоритм для каждого сертификата:**
1. Нормализует CN: `lower()`, убирает кавычки, `strip()`
2. Если `target_cn` содержится в CN сертификата → снимает `ARCHIVED`
3. Иначе → устанавливает `ARCHIVED`

**Пример:**
```
apply_filter("ДЕТСКИЙ САД №5")
→ (1, 240)  # 1 оставлен видимым, 240 скрыты
```

---

### `restore_all()` — строка 388

Снимает флаг `CERT_ARCHIVED_PROP_ID` со **всех** сертификатов.

**Особенность:** Сначала дублирует все контексты в список, затем обрабатывает.
Это необходимо, так как изменение свойства сертификата во время итерации
может привести к непредсказуемому поведению.

---

### `hide_all()` — строка 410

Устанавливает флаг `CERT_ARCHIVED_PROP_ID` на **все** сертификаты.

Аналогична `restore_all()`, но устанавливает `archived=True`.

---

### `get_all_certs() → list[dict]` — строка 432

Получает список всех сертификатов из хранилищ `MY` и `AddressBook`.

**Возвращает список словарей:**

| Ключ | Тип | Описание |
|------|-----|----------|
| `name` | `str` | CN сертификата |
| `archived` | `bool` | Скрыт ли от плагина |
| `not_after` | `datetime` | Дата окончания действия |

**Флаги открытия хранилища:**
- `CERT_STORE_ENUM_ARCHIVED_FLAG` — включён, чтобы перечислять и скрытые сертификаты
  (иначе архивированные не попадут в список)

## 11. Сценарии использования

### Сценарий 1: Фильтрация по ключу

```
1. Выбрать JSON-файл (config_fl.json)
2. Ввести номер ключа (например "145ю") → нажать OK
3. Приложение найдёт CN : "ДЕТСКИЙ САД №5"
4. apply_filter("ДЕТСКИЙ САД №5") установит ARCHIVED на все остальные
5. В плагине КриптоПро будет виден только этот сертификат
```

```
1. Выбрать JSON-файл
2. В списке нажать на нужную запись
3. Фильтрация запустится автоматически
```

```
1. Нажать "ПОКАЗАТЬ ВСЕ"
2. Все сертификаты станут видимы для плагина
```

```
1. Нажать 💾 рядом с нужным сертификатом
2. Выбрать путь для сохранения файла
3. Ввести пароль для защиты PFX
4. Файл .pfx будет создан
```

### Сценарий 5: Импорт сертификата

```
2. Выбрать .pfx файл
3. Ввести пароль

```

## 12. Безопасность

| Аспект | Описание |
|--------|----------|
| **Закрытые ключи** | Не покидают хранилище CSP, кроме явного экспорта PFX |
| **Пароли PFX** | Используются только при вызове CryptoAPI, не сохраняются |
| **Удаление** | Требует подтверждения через `QMessageBox.warning` |
| **Флаг Archived** | Обратимая операция — всегда можно «Показать все» |

---

## 13. Известные ограничения

| Ограничение | Описание |
|-------------|----------|
| **Архитектура** | Только x86_64 (путь `amd64` зашит в код) |
| **КриптоПро (Linux)** | Требуется установленный КриптоПро CSP с библиотеками в `/opt/cprocsp/` |
| **JSON-файлы** | Должны находиться в текущей рабочей директории |
| **Одинаковые CN** | Если два сертификата имеют идентичный CN, операции (экспорт, удаление) применяются к первому найденному |
| **Хранилища** | Обрабатываются только `MY` и `AddressBook` |
| **Фоновый поток** | Только для `apply_filter()`, остальные операции — в UI-потоке |
